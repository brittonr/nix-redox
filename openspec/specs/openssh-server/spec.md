## ADDED Requirements

### Requirement: sshd reads sshd_config
The sshd binary SHALL read its configuration from `/etc/ssh/sshd_config` as generated by the module system. The config file SHALL control port, listen address, host key paths, authentication settings, and address family.

#### Scenario: sshd starts with generated config
- **WHEN** sshd is started with `-D` (foreground mode)
- **THEN** it SHALL read `/etc/ssh/sshd_config`
- **AND** listen on the configured port and address

#### Scenario: Config specifies AddressFamily inet
- **WHEN** `sshd_config` contains `AddressFamily inet`
- **THEN** sshd SHALL listen on IPv4 only (IPv6 not supported on Redox)

### Requirement: Multiple host key types
The sshd SHALL load host keys for Ed25519, RSA, and ECDSA from the paths specified in `sshd_config` via `HostKey` directives.

#### Scenario: All three key types present
- **WHEN** `/etc/ssh/ssh_host_ed25519_key`, `/etc/ssh/ssh_host_rsa_key`, and `/etc/ssh/ssh_host_ecdsa_key` exist
- **AND** `sshd_config` references all three
- **THEN** sshd SHALL offer all three host key algorithms during key exchange

#### Scenario: Missing host key file
- **WHEN** a `HostKey` path in `sshd_config` points to a nonexistent file
- **THEN** sshd SHALL log a warning but continue with the remaining keys

### Requirement: SSH2 protocol with OpenSSH client
The sshd SHALL complete SSH2 handshake and establish an encrypted session with standard OpenSSH 8+ clients.

#### Scenario: OpenSSH client connects
- **WHEN** an OpenSSH client connects using `curve25519-sha256` or `diffie-hellman-group-exchange-sha256`
- **AND** the server offers `ssh-ed25519` host key
- **THEN** the handshake SHALL succeed and produce an encrypted channel

### Requirement: Password authentication
The sshd SHALL authenticate users via password. With `PasswordAuthentication yes` in sshd_config, users SHALL be able to log in with their system password.

#### Scenario: Correct password
- **WHEN** a client provides a valid username and password
- **THEN** authentication SHALL succeed and a session SHALL be established

#### Scenario: Wrong password
- **WHEN** a client provides an incorrect password
- **THEN** authentication SHALL fail

#### Scenario: Empty password policy
- **WHEN** `PermitEmptyPasswords no` is set in sshd_config
- **AND** a user has an empty password
- **THEN** authentication SHALL fail for that user

### Requirement: PTY and shell session
After authentication, when the client requests a PTY and shell, sshd SHALL allocate a pseudo-terminal and spawn the user's login shell.

#### Scenario: Interactive session
- **WHEN** authentication succeeds and the client requests a shell
- **THEN** sshd SHALL allocate a PTY
- **AND** spawn the user's shell from `/etc/passwd`
- **AND** bridge the PTY to the SSH channel for interactive use

#### Scenario: Command execution
- **WHEN** the client runs `ssh user@host 'echo hello'`
- **THEN** sshd SHALL execute the command and return its output over the SSH channel
- **AND** close the channel after the command exits

#### Scenario: Shell exit
- **WHEN** the remote shell exits
- **THEN** sshd SHALL send channel EOF and close to the client

### Requirement: Concurrent connections
The sshd SHALL accept multiple simultaneous connections. Each connection SHALL have an independent session.

#### Scenario: Two clients connected
- **WHEN** two clients are authenticated simultaneously
- **THEN** each SHALL have an independent shell session

### Requirement: Init system integration
When `/services/ssh.enable = true`, the build system SHALL start sshd as a `daemon`-type service after `ptyd` and `smolnetd`.

#### Scenario: SSH enabled in profile
- **WHEN** a profile sets `/services/ssh.enable = true`
- **THEN** the init system SHALL start `sshd -D` during boot
- **AND** `/etc/ssh/sshd_config` SHALL be generated with the configured options
- **AND** host key files SHALL be present at the configured paths

#### Scenario: SSH disabled
- **WHEN** `/services/ssh.enable` is `false` (default)
- **THEN** no sshd service or SSH config files SHALL be generated

### Requirement: Root login control
The `sshd_config` SHALL set `PermitRootLogin` based on the module option `/services/ssh.permitRootLogin`.

#### Scenario: Root login permitted
- **WHEN** `permitRootLogin = true`
- **THEN** `sshd_config` SHALL contain `PermitRootLogin yes`
- **AND** root SHALL be able to authenticate via SSH

#### Scenario: Root login denied
- **WHEN** `permitRootLogin = false`
- **THEN** `sshd_config` SHALL contain `PermitRootLogin no`
